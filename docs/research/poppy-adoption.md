# Poppy adoption and stability: go/no-go input

Research date: **2026-10-11**. Resolves [Poppy adoption and stability (go/no-go input)](https://github.com/fillthemat/fillthemat/issues/123), within [Map: Fit Fillthemat into Personal Agent Protocol (Poppy)](https://github.com/fillthemat/fillthemat/issues/122). Research-only branch; not intended to merge.

## Bottom line

**Conditional GO for a disposable, tightly capped interoperability spike; NO-GO for a production rollout or substantial platform investment today.** Confidence: **medium-high** in this recommendation; high in the dated draft/announcement/package facts; medium in ecosystem completeness and actual deployment availability.

Poppy has credible sponsors, one first-party-described live Meta Muse ↔ Rocket demonstration, and several independently implemented clients and Company servers. It is not merely a slide deck. But partner logos are not deployments, public production uptake is not established, the official reference implementation is still promised, and the draft explicitly allows breaking changes. TypeScript/Node options now exist, but are days old and moving fast. [Sierra's Oct 9 announcement](https://sierra.ai/blog/poppy), [spec §1](https://personalagentprotocol.org/docs/spec#intro), [Datalayer compatibility](https://github.com/datalayer/personal-agent-protocol/blob/v0.9.0/docs/docs/releases/compatibility.mdx), [Poppyseed](https://github.com/akshay5995/poppyseed/blob/f479fb6bd1754b9639440515f259e01936b0a18a/README.md).

## Stewardship and governance

- **Practical stewards: Sierra and Meta**, developing the protocol with the named industry/design partners. Sierra founders Bret Taylor and Clay Bavor publish the announcements and workshop/reference-implementation roadmap. [Oct 6](https://sierra.ai/blog/introducing-personal-agent-protocol), [Oct 9](https://sierra.ai/blog/poppy).
- Spec/docs/examples are **Apache-2.0**, including a contributor patent license; names/logo/site design are excluded. Contributions and feedback have explicit licensing terms. [License](https://personalagentprotocol.org/license), [contributions](https://personalagentprotocol.org/license/contributions).
- I found **no authenticated official spec GitHub repository** linked from the homepage, spec, overview, license/contribution pages, sitemap, or Sierra announcements. Searches surfaced independent implementations and unrelated projects named Poppy. In particular, `datalayer/personal-agent-protocol` is an SDK repository, and `akshay5995/poppyseed/spec/source` is a copied upstream snapshot: neither is the steward-owned specification repository. [Official sitemap](https://personalagentprotocol.org/sitemap.xml), [Poppyseed snapshot explanation](https://github.com/akshay5995/poppyseed/blob/f479fb6bd1754b9639440515f259e01936b0a18a/spec/README.md).
- The inspected official pages do not document a foundation/standards-body transfer, voting rules, maintainer roster, release guarantees, or a stable-version date. **Unknown, not proof none exists privately.** Ask the stewards for the canonical repo, change process, public client availability, and official interop harness before making a long-lived dependency decision.

## How fast is Draft 0.1 changing?

### Measured observations

1. **Oct 6:** announcement says v0.1 is planned later that month. **Oct 9:** the draft actually publishes, and Sierra promises workshops and a reference implementation “over the next month.” This is a two-day-old public draft on the research date. [Oct 6](https://sierra.ai/blog/introducing-personal-agent-protocol), [Oct 9](https://sierra.ai/blog/poppy).
2. The official docs header still reads **Draft 0.1 / Updated Oct 9, 2026**. [Spec](https://personalagentprotocol.org/docs/spec).
3. A useful independent observation window exists: Poppyseed committed a snapshot whose `FETCHED_AT` is **2026-10-10T10:05:46Z**. On Oct 11 I fetched its pinned source and the official Markdown endpoints and compared their full decoded text. **All four matched exactly**: spec, guides, Operations extension, and open topics. This establishes no net text change between those two fetches, **not** a day-by-day history or proof of stability. [Snapshot timestamp](https://github.com/akshay5995/poppyseed/blob/eb7b6a9fb795b29638fccbd69bdefb2b141dc1dd/spec/source/FETCHED_AT), [snapshot spec](https://github.com/akshay5995/poppyseed/blob/eb7b6a9fb795b29638fccbd69bdefb2b141dc1dd/spec/source/docs/spec.md), [official spec Markdown](https://personalagentprotocol.org/docs/spec.md), [guides Markdown](https://personalagentprotocol.org/docs/guides.md), [Operations Markdown](https://personalagentprotocol.org/docs/extensions/operations.md), [open-topics Markdown](https://personalagentprotocol.org/docs/open-topics.md).
4. **Implementation churn is demonstrably high:** npm records **11 non-stage Datalayer versions** on Oct 10–11: 0.2.0, 0.3.0–0.3.3, and 0.4.0–0.9.0. Its changelog labels breaking storage/API/contribution changes, and support covers only the latest minor. This is SDK churn, **not eleven spec revisions**. [Registry timestamps](https://registry.npmjs.org/@datalayer%2fpersonal-agent-protocol), [changelog](https://github.com/datalayer/personal-agent-protocol/blob/v0.9.0/CHANGELOG.md), [support policy](https://github.com/datalayer/personal-agent-protocol/blob/v0.9.0/docs/docs/releases/support.mdx).

### Contractual stability

The spec says **any part can change incompatibly before stable**. Discovery's general minor-version compatibility rule must not be mistaken for protection against edits within this draft. Payments, push notifications, and attachments remain explicitly open. Post-booking reminders to Personal Agents therefore lack a defined push mechanism. [Spec §§1, 3.1](https://personalagentprotocol.org/docs/spec), [open topics](https://personalagentprotocol.org/docs/open-topics).

With no authenticated official source repository/history identified, a commit rate, contributor count, or reliable breaking-change cadence for the **spec itself** cannot be calculated. The right conclusion is **little observed text movement in a tiny window, but no stability guarantee**, not “rapid daily breaking spec changes” or “stable already.”

## What “cheap first step” means for Fillthemat

This is a recommendation, not an authorization to implement or a finished design.

- **Budget gate:** allow at most one engineer-day for a disposable spike, with no production booking writes, no promised launch, and no dependence on real Personal Agent traffic. Prefer evaluating pinned Poppyseed Company code against an independently authored client (Datalayer or pi-poppy). Stop if tenant identity or secure Session issuance pushes it beyond that cap.
- **Useful spike outcome:** one HTTPS School identity → signed-out Session → School Catalog read or harmless Assistant conversation. Verify isolation between two School identities, metadata/issuer checks, DPoP binding, replay handling, and retries. Independent interoperability is the deliverable; SDK self-tests alone are insufficient.
- **Do not mistake a manifest for the product.** A web-only `poppy.json` may omit `auth` and just point agents at ordinary signed-out browsing. Adding `agent` or `apis` requires `auth` and real Session issuance even for guests. Discovery-only can be cheap, but does not enable Poppy conversations or booking. [Spec §§3.1, 4.1–4.3, 5](https://personalagentprotocol.org/docs/spec).
- **School isolation is a genuine cost.** Discovery is per host, `organization.domain` must match that host, and domains sharing one `auth.issuer` are one Company. Existing `/s/[slug]` URLs cannot each declare their own host identity. A School-as-Company design needs a domain/subdomain and issuer plan, not a single shared Fillthemat manifest. Redirecting discovery to a hosted service is allowed. [Spec §§3, 3.2](https://personalagentprotocol.org/docs/spec).
- **Booking is a later gated step.** Operations v1 can model a proposed trial booking with exact terms, explicit user approval, and at-most-once confirmation. Preserve Fillthemat's rule that the Assistant prepares a Booking Intent and the platform books. Set `user_approval_required` where explicit approval is needed; do not treat conversational “yes” as an Operations confirmation. An agent's approval claim is not cryptographic proof the human approved. [Operations §§3–6, 8](https://personalagentprotocol.org/docs/extensions/operations), [coding standards](../../CODING_STANDARDS.md).
- **Promotion gate:** before production, require a reachable target Personal Agent/distribution channel or actual School demand, independent interop evidence, reviewed multi-tenant security/storage/abuse controls, and a steward change-tracking route. Revisit after the announced reference implementation/workshops (roughly the next month), or sooner if a real partner offers a pilot. No calendar promise is implied.

## Evidence limits

Primary sources were the official spec/license pages, Sierra and OneSignal announcements, implementation authors' repositories and pinned tags/commits, and direct npm/PyPI metadata. GitHub/web search was used to locate sources; unrelated Poppy robotics/ML packages, A2A, PACT, and general MCP integrations were not counted. No candidate code was executed, no security audit performed, and no real consumer-to-Company transaction attempted.
